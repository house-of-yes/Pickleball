# Pickleball Development

*Play your way to flow.*

A lightweight feedback-loop for building in rhythmic rallies — **serve → rally → call → point → reset**.  
**Created by HOY POLLOI 1.0 (Anima & Clem).** Built in public.

---

## 🏓 What It Is

Pickleball Development is a practice for software and creative work that replaces sprints with rallies.  
Each loop is small, inspectable, and honest.  
Momentum replaces motivation. Rhythm replaces rush.

| Phase | Meaning | Action |
|-------|----------|--------|
| **Serve** | Declare intent | Propose the smallest tangible change |
| **Rally** | Move the ball | Code → run → observe |
| **Call** | Name what happened | Pass / fail, foul / flower |
| **Point** | Land the win | Merge, ship, log the metric |
| **Reset** | Clear the court | Archive, breathe, begin again |

This loop can be run solo or with a team.  
It works equally well for codebases, art projects, and community building.

---

## ⚙️ Quickstart

    # Initialize your loop
    ./tools/pickleball.sh serve "Add healthcheck endpoint"

    # Rally your change
    ./tools/pickleball.sh rally

    # Call the result
    ./tools/pickleball.sh call "passes locally"

    # Record your point
    ./tools/pickleball.sh point

    # Reset for the next serve
    ./tools/pickleball.sh reset

For a deeper dive, see `docs/loop.md`.

## 🧠 Philosophy

- **Small serves.** Scope down until momentum feels effortless.  
- **Short rallies.** Don’t wait for perfection — just return the ball.  
- **Explicit calls.** Write what happened; truth is the metric.  
- **Points are merges.** Celebrate learning, not just shipping.  
- **Resets are sacred.** Each new serve is a fresh court.  

This project lives at the intersection of engineering, art, and myth.  
Its goal is not to manage time, but to *tune rhythm.*
